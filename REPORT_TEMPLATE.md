REPORT — САП КОД AI-разработчик

1. Что было сломано
Изначальная реализация process_event не соответствовала бизнес-требованиям: отсутствовала дедупликация заявок (каждый вызов создавал новую запись), не было валидации входных данных (пустые строки и числа принимались как валидные), а на ОС Windows возникали ошибки блокировки файлов (PermissionError) при удалении временных баз данных тестами.

2. Что исправлено

Реализована строгая валидация: проверка типов всех полей (str) до применения методов строк, а также проверка на пустоту после strip().
Добавлена дедупликация по паре (source, external_id). Повторные запросы возвращают статус duplicate и ID первой записи без создания новых строк в leads и notifications.
Реализована нормализация данных: обрезка пробелов по краям для source, external_id, customer и message.
Устранена ошибка PermissionError на Windows за счет использования with sqlite3.connect и корректного порядка операций.
Добавлены два собственных теста (test_empty_message_is_invalid, test_source_case_sensitivity) для покрытия граничных условий.

3. Как проверено

Команда: python -m unittest discover -s tests -v.
Результат: Все 8 публичных тестов SAP пройдены (ok). Общее количество тестов с учетом добавленных — 10, все OK.
Дополнительно: Проверена изоляция БД (отсутствие блокировок файлов), проверена логика сохранения первого события при повторной отправке с измененным текстом.

4. AI-инструменты
Использовался GigaChat. Инструмент применялся для анализа трассировок ошибок (PermissionError, AssertionError), генерации архитектурных вариантов решения проблемы с файловой системой Windows (WAL, задержки, уникальные файлы) и написания финального кода функции process_event и юнит-тестов. Вся бизнес-логика валидирована и проверена лично на соответствие требованиям README.md.
